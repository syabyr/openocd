# 06 — 时钟模型与标定方法

速度从哪里来、到哪里去、怎么测。本章数字全部实测（BBB + prupoke，
md5 门禁的倾倒交叉验证）。

## OCP 物理节拍（理解一切的前提）

PRU 访问 GPIO1 寄存器走 OCP 主端口（L3 互连），两类访问代价天差地别：

| 访问类型 | 例子 | 代价 |
|---|---|---|
| **OCP 写** | SETDATAOUT/CLEARDATAOUT（驱 SWDIO/SWCLK） | **fire-and-forget 流水**：PRU 发出即走，~150ns/个背靠背 |
| **OCP 读** | DATAIN（采样 SWDIO） | **全延迟阻塞**：PRU 停等数据返回，~300ns |

推论：
- stock 方案每时钟 2 个 OCP 写（SWCLK 边沿）×流水≈440ns/时钟 →
  这就是 iters=0 的"OCP 地板"2.28MHz
- 采样时钟（36/48）额外 1 个 OCP 读，被写流水掩护大半——总账仍是
  ~440ns/时钟量级（批量倾倒实测平均值）
- **真正的墙是每采样位的 OCP 读**——R30 实验（[07](07-r30-experiment.md)）
  把写全免了也只有 553ns/采样时钟，就是被这个读顶住的

## half_phase 的固定开销

```c
volatile uint32_t n = MBOX[MBOX_DELAY];
while (n--) __delay_cycles(1);
```

反汇编：入口 ~10 条（volatile 局部变量走栈，DRAM LBBO/SBBO），
循环体 8 条/迭代。实测折算：固定 ~145ns/半相位 + **160ns/迭代**。
stock 方案里这部分藏在 OCP 写节拍下面（地板 440 > 2×145+开销），
所以延迟档从 iters=1 才开始起作用。

> 想优化它：把局部变量 volatile 去掉让它落寄存器（~20ns/迭代）。
> 但这会改变全部档位标定，且 stock 方案受益为零（OCP 掩护着），
> 留给硬件路线（[08](08-hardware-roadmap.md)）一并做。

## 标定方法（prupoke t 模式）

```sh
./prupoke t <iters> <clocks>
# SIG_IDLE × 20 次摊销 → ns/clock（idle 时钟：无数据 OCP，纯节拍）
# 末尾一条 READ_REG 单事务计时（参考值）
```

三条铁律：
1. **摊销**：单命令有邮箱/轮询开销，20 次平均
2. **总时长 ≥3× 轮询地板**：usleep(1000) 轮询地板 ~1ms，命令必须
   跑到 ~3ms 以上才不被污染（低速档 5000 时钟够，快时钟加到 20000）
3. **idle 与 xact 分开测**：idle 测节拍本体，xact（48 时钟含 36 采样）
   测真实数据路径——两者差值 ≈ OCP 读代价

## 实测数据

### stock 固件（GPIO-over-OCP 双线）

| iters | idle ns/时钟 | 备注 |
|---:|---:|---|
| 0 | 439 | OCP 写流水地板 = 2.28MHz 实测 |
| ≥1 | 439 + 160×iters | 斜率 160，驱动取 190 保守 |

倾倒交叉验证（256 KiB，md5 全对）：

| 请求 | iters | 实测线速 | 耗时 |
|---:|---:|---:|---:|
| 2000 kHz | 0 | ~2.28 MHz | 1.81 s |
| 1800 kHz | 1 | ~1.9 MHz | 2.3 s |
| 1000 kHz | 4 | ~1.0 MHz | 3.7 s |
| 500 kHz | 9 | ~0.55 MHz | 6.2 s |
| 300 kHz | 16 | ~0.35 MHz | 9.5 s |

### R30 实验固件（SWCLK 免 OCP，仅 SWDIO 走 OCP）

| iters | idle ns/时钟 | 读事务 ns/时钟 |
|---:|---:|---:|
| 0 | 290 | 553 |
| 1 | 450 | 714 |
| 2 | 610 | 873 |
| 4 | 930 | 1193 |

解读：idle 降到 290（写免费了）但**读事务反升**——SWCLK 写的 OCP
流水没了，OCP 读赤裸裸上关键路径（553 > 439）；iters=0 还有写位
竞争崩溃（[07](07-r30-experiment.md#失败机理)）。

## 驱动映射推导

目标：任给请求周期，选不超过它的最近档（宁快勿慢——SWD 慢无危害，
错位才致命；但也不能快到信号完整性出事，所以是"最近不超"）。

```
period_ns ≤ 550  → iters = 0           （OCP 地板兜底）
period_ns > 550  → iters = (period_ns - 222) / 190   （截断取整）
```

- 222 = 固定开销折算（半相位固定 145×2 ≈ 290，但 iters=0 地板 439
  已含——线性段的截距按 iters=1 档反推）
- 190 = 斜率上界（实测 160，DRAM 访问抖动留 30 余量）
- 档位实速可能略超请求（整数粒度），≤~15%，可接受

## 天花板总结

| 方案 | 瓶颈 | 实测上限 |
|---|---|---|
| stock（双线 OCP） | OCP 写流水地板 | 2.28 MHz（1.81s/256KiB） |
| R30 混合 | OCP 读/采样位 + 写竞争 | **负收益**，弃 |
| 硬件路线（[08](08-hardware-roadmap.md)） | half_phase 节拍 + 信号完整性 | 预估 4–8 MHz |

host 侧（邮箱轮询/4 KiB 拷贝）在 2.28MHz 下已被批量读摊薄到不可见；
到 4–8MHz 后需要重新核对 host 开销占比。
