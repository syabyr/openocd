# 08 — 硬件改线路线图：电阻弱驱全本地 SWDIO

突破 2.28 MHz OCP 天花板的唯一现实路径。**已实施并验证（2026-08-20）**：
本文原为设计文档，照此改线后软件（V3 固件/驱动/dts，分支 pru-swd-r30）
一次点亮，256 KiB 倾倒 0.547s（468 KiB/s，~5.4 MHz），md5 门禁全过。
实施记录与实测数字见 [06](06-timing.md#v3-固件硬改后swclkswdio-全-pru-本地引脚)
与 [05](05-board-bringup.md#设备树v3-硬改方案)。

## 核心障碍与绕法

全本地 SWDIO 的障碍：PRU 输出脚（R30 mux）**无法三态**，而 SWD 读
换向必须释放 SWDIO（否则与目标强对强争总线）。

绕法：让 host 永远**弱驱**。SWDIO 网络上串一个电阻，host 经电阻
驱动；目标直接驱动（强）。两者冲突时目标必胜，host 从不需要松手
——"伪开漏"（实为弱推挽），OE 翻转、OCP 读全部消失。

## 接线

```
                                          目标侧
P8_12 (R30.14) ────────────────────────── SWCLK   （直连，单向）
P8_11 (R30.15) ──[ 1 kΩ ]──┬────────────  SWDIO
P8_15 (R31.15) ─────────────┘              （直入，只读）
P8_26 (GPIO1_29) ───────────────────────── nRST   （P8_15 让出，挪此）
GND ────────────────────────────────────── GND
```

改动步骤（断电操作）：
1. 目标 SWDIO 从 P8_11 断开
2. P8_11 → 1 kΩ 电阻 → 新节点；节点 → 目标 SWDIO
3. 节点另引线 → P8_15
4. nRST（若在用）从 P8_15 挪到 P8_26（GPIO1_29，mode 7，OCP 慢速
   无所谓）
5. 线束 <15 cm，SWCLK 直连强驱没问题

## 电气核算

**目标高阻（host 驱动阶段：请求位/写数据/idle）**
目标输入漏激 µA 级 → 1 kΩ 压降 mV 级 → 目标看到完整摆幅。✓

**目标驱动（ack/读数据阶段，host 不松手）**
目标强驱输出阻抗 ~25 Ω vs host 经 1 kΩ：

| 冲突 | 节点电压 | 判读 |
|---|---|---|
| host=1（经 R）, 目标=0 | 3.3 × 25/1025 ≈ 0.08 V | 读 0 ✓ 目标胜 |
| host=0（经 R）, 目标=1 | 3.3 × 1000/1025 ≈ 3.22 V | 读 1 ✓ 目标胜 |

争用电流 3.3 V / 1 kΩ = 3.3 mA，远低于 25 mA 管脚上限，**可持续**。
读阶段 host 侧宜预驱 0（弱下拉兼作 SWD 要求的 idle 低电平）。

**边沿速度（RC）**
1 kΩ × 线电容 ~30 pF（杜邦线+管脚）≈ 30 ns → 支撑 4–8 MHz。
（若用 3.3 kΩ：RC≈100 ns，限到 ~2 MHz——别。470 Ω 也行，争用
7 mA 仍安全，但 1 kΩ 是甜点。）

**附带保险**：电阻同时防呆——忘串电阻才是危险工况（两强驱对打）。

## 软件改动清单

### 固件 pru-swd.c（主体）

```c
#define SWDIO_R30 (1u << 15)          /* P8_11 弱驱输出 */
#define SWDIO_R31 (1u << 15)          /* P8_15 只读输入 */
#define SWCLK_R30 (1u << 14)

static inline void dio_drive(uint32_t mask_hi) {
    __R30 = (__R30 & ~SWDIO_R30) | mask_hi;   /* 单周期 */
}
static inline uint32_t dio_sample(void) {
    return __R31 & SWDIO_R31;                 /* 单周期 */
}
/* dio_set_input / dio_set_output（OE 翻转）：删除
   trn_input：退化为纯时钟（或兼驱弱 0） */
```

- nRST 的 `CMD_GPIO_OUT` 保留 OCP 路径，mask 改 `1u << 29`
- `half_phase` 重写：去 volatile 局部变量（寄存器计数 ~20ns/迭代），
  节拍粒度变细后全档重标定
- 校验 `dio_sample` 的 R31 读路径用 dispru 确认真读 R31（大写）

### 设备树

```
GPMC_AD13 (P8_11) MODE6                r30_15 输出
GPMC_AD12 (P8_12) MODE6                r30_14 输出
GPMC_AD15 (P8_15) MODE6 + 接收使能      r31_15 输入
GPMC_WEN  (P8_26) MODE7 + 上拉 hog     nRST（GPIO1_29）
```

### OpenOCD 驱动

- 速度映射常量全部重标定（`PRU_MAX_KHZ` 目标 6000–8000，视实测）
- nRST 位掩码 15 → 29；退出清理不再还原 SWDIO 的 GPIO1 OE
- `swd_pin_mask` 相应调整

### 文档与验证

- README 接线表 + 争用原理；[05](05-board-bringup.md) 部署流程复用
- 门禁不变：各档 `flash read_bank` md5 = 424c5ecd；先 1000 kHz 冒烟
  再爬速度

## 预期与风险

| 项 | 估算 |
|---|---|
| 线速 | 4–8 MHz（half_phase 寄存器循环后受信号完整性限） |
| 256 KiB 倾倒 | @4 MHz ≈ 0.8 s；@8 MHz ≈ 0.4 s（现 1.81 s） |
| 新瓶颈 | host 邮箱轮询/4 KiB 拷贝占比上升；STM32 SWD 上限；线束质量 |

风险：
- 杜邦线过长时 8 MHz 边沿反射——降档即好，门禁会抓住
- 若目标板 SWDIO 自带强上拉/串联元件，与 1 kΩ 分压需复核阈值
  （实测 VIH/VIL 裕量：0.08 V / 3.22 V，裕量极大，一般无忧）

## 实施顺序建议

1. 固件先在分支上改好、宿主单元验证（dispru 查 R30/R31 引用）
2. dtb 三脚 MODE6 + P8_26 MODE7
3. 断电改线（本文接线图）
4. prupoke 自检 → 1000 kHz 枚举冒烟 → md5 门禁逐档爬升
5. 全档通过后：prupoke t 重标定 → 驱动常量 → 全档复验 → 提交
